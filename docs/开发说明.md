# 简单图床插件：开发说明

面向维护者。用户教程见根目录 `readme.md`（会打进插件包）。

## 目录结构

```text
简单图床/
├── plugin.json       插件元信息（会被打进 ZIP 根目录）
├── uploader.json     程序入口：配置字段、权限、上传与删除请求
├── readme.md         用户教程（打进 ZIP）
├── LICENSE
├── assets/icon.svg   插件图标（打进 ZIP）
├── tools/pack.ps1    打包脚本，不进入 ZIP
├── docs/开发说明.md   本文件，不进入 ZIP
└── releases/         打包产物，不进入 ZIP
```

ZIP 根目录必须直接是 `plugin.json` / `uploader.json` / `readme.md` / `assets/`，不要再套一层文件夹。

## 打包

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\pack.ps1 -Force
```

默认输出 `releases/easyimages2-<version>.picora-plugin.zip`，并打印大小与 SHA256。脚本会校验
`packageVersion`、`runtime` 与入口 `schemaVersion` 是否匹配、SemVer、条目数与单文件大小。

发布到模块仓库时，Release 附件名必须以 `.picora-plugin.zip` 结尾（注意是点号），例如
`easyimages2-1.0.0.picora-plugin.zip`。

## 接口要点（EasyImages2.0）

来自 [docs/API.md](https://github.com/icret/EasyImages2.0/blob/master/docs/API.md) 与 `api/index.php` 源码：

| 项目 | 说明 |
| --- | --- |
| 上传地址 | `POST {站点}/api/index.php`，multipart |
| 文件字段 | `image` |
| 鉴权 | 表单字段 `token`；服务端用 `preg_replace('/[\W]/','')` 过滤，只保留字母数字 |
| HTTP 状态 | 业务失败也返回 **200**，必须靠响应体判断 |
| 成功标志 | `result == "success"`（2.1 起到 2.8 都存在该字段） |
| 图片链接 | `url`；`thumb` 缩略图；`del` 删除链接（2.8 起为 JSON 接口） |
| 业务错误 | `code`（201/202/203/204/205/400）+ `message` |
| 删除 | 对 `del` 链接发 GET，返回 JSON `{code,msg,type,...}`，`code == 200` 为成功 |

因此插件里 `successStatuses: [200]` + `success: {path: "result", equals: "success"}`，
删除用 `success: {path: "code", equals: 200}`。

## 两个设计取舍

1. **删除链接放在 `deleteKey` 而不是 `deleteUrl`。**
   站点关闭「用户删除链接」时，`del` 字段返回的是字符串 `Admin closed user delete`。
   `deleteUrl` 会在**上传阶段**就做 URL 校验，一旦站点关闭该功能，上传会整体报错；
   放进 `deleteKey` 则上传照常成功，只有真正删除时才提示「插件生成了无效的请求地址」。
   删除请求模板为 `"url": "${upload.deleteKey}"`。

2. **`network` 用 `config.baseUrl` 绑定用户填写的地址。**
   自建图床域名不固定，不能写死主机；v2 允许用配置项绑定协议、主机与端口。
   `allowInsecureHttp: true` 是为了兼容内网 / HTTP 自建站点，公网建议 HTTPS。
   副作用：删除链接的域名必须与图床地址同源，站点 `domain` 配置与访问域名不一致时删除会被拦截。

## 已验证内容

用 Picora 自身的 `PicoraPluginPackage.decode` + `PluginHttpRuntime`（Dio 打桩）跑过：

- ZIP 安装、元信息、权限、模板引用全部通过安装期校验；
- 上传请求为 `POST {baseUrl}/api/index.php`，multipart 文件字段 `image`、附加字段 `token`，末尾斜杠会被规范化；
- 成功响应解析出 `url` / `thumb` / `del`，`del` 写入上传记录的 `deleteKey`；
- `result: failed` + `code: 202` + `message: Token Error` 时抛出「简单图床：Token Error」；
- 删除按记录的 `del` 链接发 GET，`code == 200` 视为成功；`code: 404` 时提示「文件不存在」；
- 配置修订变化后拒绝删除；`del` 不是链接时删除报「插件生成了无效的请求地址」。

没有对公网真实站点做端到端上传（原文档里的演示站已下线），上线前建议用一台自建简单图床实机验证一次上传与删除。

## 提交到模块仓库

1. 在独立公开仓库发布 Release，上传 `.picora-plugin.zip`。
2. Fork `Alnitak44/picora-plugins`，新增 `registrations/io.github.alnitak44.picora.easyimages2.json`：

```json
{
  "id": "io.github.alnitak44.picora.easyimages2",
  "releaseRepository": "Alnitak44/picora-plugin-easyimages",
  "assetPrefix": "easyimages2-",
  "minAppVersion": "1.0.7",
  "approvedPermissions": {
    "network": ["config.baseUrl"],
    "readSelectedFile": true,
    "allowInsecureHttp": true,
    "deleteUploadedFile": true
  }
}
```

`plugin.json` 的 `repository` 必须与 `releaseRepository` 指向同一个仓库根地址；
`approvedPermissions` 必须与 `uploader.json` 的 `permissions` 完全一致，任何权限变化都要重新审核。

## 维护约定

- `id` 与 `config.key`（`baseUrl`、`token`）发布后不要改，否则用户配置与上传记录会失效。
- 改请求、响应路径或权限时递增 `version`，并在 `readme.md` 的错误对照表同步更新。
- 站点若调整接口（例如新增必需参数），优先用 `config` 字段加开关，不要破坏旧配置。

## 属性标签

1.1.0 起按 Picora `1.0.7` 的 `config[].role` 约定声明字段语义，客户端据此在插件列表里显示标签（登记文件不需要写标签）：

| 字段 | `role` | 推导出的标签 |
| --- | --- | --- |
| `baseUrl` | `endpoint` | 自定义地址 |
| `token` | `token` | Token |
| 声明了 `delete` 请求 | —（自动） | 云删除 |

`token` 是必填的 `secret` 字段，因此列表会显示「需认证」。使用 `role` 后最低 Picora 版本提升到 `1.0.7`，登记文件 `minAppVersion` 已同步。
